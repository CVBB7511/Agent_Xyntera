## 本机开发，BYL 运行

在本机运行 Codex，在当前本地项目文件夹编写和修改代码。本地文件是唯一的代码来源。运行前，通过 SSH 将本次所需的代码、配置和输入同步到 BYL 的项目根目录，并确认目标路径与同步内容。BYL 上的项目代码只通过同步更新。根据远程日志定位问题后，在本机修复并重新同步，再在 BYL 重跑。

## 每次启动 GPU 任务前

1. 用 `nvidia-smi --query-gpu=index,uuid,name,memory.used,memory.total --format=csv` 查询所有 GPU。**整卡显存占用严格低于 75% 的卡计为空闲**。
2. 若整机空闲 GPU 少于两张，或显存状态无法确认，停止本次启动并说明原因。至少两张空闲时，从中选择显存占用比例最低且能给本任务留出分配余量的 A800。启动条件只用显存判断。
3. 临启动再次确认这项条件仍满足，并用 `CUDA_VISIBLE_DEVICES=<所选 GPU UUID>` 把任务限制在这张卡。每次新启动、重试或恢复都重新执行检查。BYL 通过普通 SSH 运行，使用本技能的资源与路径规则。

## GPU 运行期间

- 给同卡任务留出显存余量。PyTorch 的进程级显存分配上限默认用单卡总显存的 70% 减去启动前该卡已用显存。其他运行时使用对应的进程级限制。
- 启动后只监测所选卡的整卡显存。查询超时或无返回时保持任务运行并自动重查。**采样到显存达到 75%，或连续三次查询都无法确认显存状态时，停止本项目任务**，并记录峰值显存和查询失败次数。根据当前任务需要可采用更低的显存门槛。
- 只结束自己启动的任务进程或进程组，记录触发原因和观测值，并确认任务已退出。显存限制和监控应局限于本任务进程，不改整卡或服务器的配置。无法设置进程级限制或运行期监控时，跳过本次 GPU 启动。
